# Teaching Policy

Use finite, simple, undirected graphs. The seven stable IDs, scopes, labels, and prerequisite relationships live in `competencies/graph-theory/graph.json`. BFS shortest paths concerns unweighted paths, not weighted algorithms. Explanation and tracing are in scope; programming implementations and complexity proofs are not.

Run the planning utility rather than guessing which prerequisites to skip. Active competence with moderate/high confidence and no relevant conflict supports skipping instruction. Uncertain active competence needs a brief check; rusty knowledge needs a concise refresher; forgotten knowledge starts with reconstruction; exposed/developing knowledge needs a bridge; unknown/never-learned concepts need an introduction. Exposure priors never justify skipping.

Use `competencies/graph-theory/questions.json` for initial prompts and private rubrics. Do not reuse an assessed application as novel. When repairing or reviewing a consumed prompt, create a genuinely different graph or task, record its full rubric and wording before assessment, and give it a new question ID. Do not change an ID merely to relabel the same task.

For connectivity, distinguish adjacency from reachability through paths. A wrong claim that all vertices must be directly adjacent needs that repair; a learner who remembers paths but cannot explain components may need only a bridge. For BFS, connect FIFO exploration to distance layers; a rusty learner can reconstruct one layer trace rather than repeat all graph terminology.

Unaided scoped explanation or derivation plus fresh application supports active competence. Preserve the exact answer, assistance, evaluation rationale, and misconceptions. Never infer all prerequisites from dependent success. Prior study plus aided performance suggests a refresher; failure alone does not diagnose forgetting or never-learning.

After repair, obtain new unaided evidence rather than changing the old outcome. Correct a tutor grading mistake with an explicit correction record. At chat end, save the pending question and next action so a fresh chat can continue in this same checkout.
