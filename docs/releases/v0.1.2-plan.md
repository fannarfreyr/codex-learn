# v0.1.2: Broad Competency Calibration

Status: implemented; automated, scripted, and live fresh-chat acceptance validation passed. See the [release validation record](v0.1.2.md).

## Findings and scope

The primary defect is calibration policy, reinforced by the skill and documentation:

- `scripts/calibration.py` explicitly returns `useful_boundary_found` after two responses leave a concept unresolved and no prerequisite question is selected.
- Selection favors prerequisite descent and same-concept confirmation before broader coverage. Eight turns can therefore omit entire branches.
- Budget exhaustion currently ends a run permanently. Session validation caps budgets at eight, and the CLI exposes no budget option.
- The learner projection already supports independent concept evidence and capability outcomes. Downstream success does not credit prerequisites; this behavior should remain unchanged.

An isolated synthetic reproduction stopped after connectivity and two terminology questions, leaving BFS, DFS, and shortest paths untested. All 56 existing tests pass, including a test that expects boundary stopping.

Limit this release to deterministic selection, calibration checkpoints, tests, and documentation. Retain seven concepts, existing graph relationships, the fourteen-question bank, standard-library Python, and one writer.

## Calibration strategies and coverage policy

Add `survey` and `focused` strategies within the existing calibration module, sharing evidence handling and checkpoint recovery.

**Survey — default for whole-area requests**

- Scope includes all seven graph-theory concepts. Prerequisite readiness never blocks diagnostic sampling.
- Reuse previous direct assessments, clearly identifying historical evidence versus observations from this survey. Credentials and self-report do not satisfy assessment coverage.
- First sample concepts lacking a current-scope explanation/derivation or application/problem-solving assessment. Incorrect, partial, and aided attempts establish tested coverage, not competence. Skips do neither.
- Preserve the current starting preference: connectivity with mapped medium/high exposure, otherwise terminology. Thereafter use stable concept order among uncovered concepts before repeating a concept. Defer concepts skipped during this survey until other available concepts have been sampled.
- Prefer explanation for initial sampling; prefer application when the learner reports knowing the idea without its name.
- After breadth sampling, prioritize follow-ups in this order: conflicting evidence; explanation-versus-application discrepancies; missing evidence needed to confirm a demonstrated strength; further characterization of unresolved gaps. Break ties by stable concept order and then bank order.
- Use effective corrected evaluations and existing readiness rules. Do not require equal question counts.
- A foundational gap never triggers survey-wide boundary stopping. Finish when no informative unused prompt remains or all scoped concepts already have supported readiness; pause at the response budget.

Return an inspectable coverage report from selection and resumption. For every scoped concept, show assessment/capability references, whether it was tested now or previously, skipped/deferred participation, remaining uncertainty, and prompt availability. Include the selection rationale and reason for pausing or ending. Derive this report from evidence and checkpoint metadata, rather than maintaining another authoritative learner model.

“Every concept sampled” describes breadth coverage only. It must never imply that the area is mastered or fully understood.

**Focused — target-specific readiness**

- Require a supported target; examine only that target and its prerequisite closure.
- Start with the deepest unresolved concept, allowing target questions before prerequisite mastery is established.
- Retain existing success confirmation, prerequisite redirection, and useful-boundary stopping within that closure.
- Stop when the scoped path has supported readiness, a defensible teaching/refresh boundary is established, or informative prompts are exhausted. Report uncertainty explicitly.
- Never fall back to unrelated graph branches.

Continue using existing capability evidence and `knows_without_name` self-report to distinguish terminology retrieval from application. A failed explanation followed by successful application remains a mixed profile, not automatic prerequisite mastery. Teaching may use directly demonstrated BFS/DFS knowledge to refresh connectivity without changing its estimate.

## Interfaces, bounds, and compatibility

Expose these operator options and their natural-language equivalents:

| Operation | Interface and behavior |
| --- | --- |
| Start | `calibrate --strategy survey\|focused --target TARGET_ID --budget N`; defaults to survey and eight response turns |
| Focused target | Required for focused; reject a target supplied with survey |
| Budget | Integer 1–14 per bounded block; response turns, not evidence-record counts |
| Pause | `pause SESSION_ID`; preserve the pending question and survey progress |
| Continue | Existing `next SESSION_ID`; add `--budget N` to resume a paused calibration with that many additional turns |
| Stop | Existing terminal `stop SESSION_ID`; retain evidence and summarize incomplete coverage |

Natural-language “continue calibration” resumes a paused run with another eight-turn block unless the learner specifies a different budget. Plain `next` must not silently extend a paused run. Repeating a continuation while already active must not replenish its budget.

Use a version-2 calibration checkpoint containing strategy, optional target, status, pause/stop reason, block budget and cumulative response limit, plus existing evidence references, consumed prompts, pending question, and recovery sequence. Teaching checkpoints remain version 1.

- Budget exhaustion pauses rather than terminates new calibrations.
- Record and consume the final answered prompt before checking the budget, including self-report-only answers.
- Preserve unanswered questions across pauses; recover saved answers before selecting again.
- Shared-turn assessment/self-report records count once; corrections count zero.
- Keep assessed-question exclusion and application novelty rules. Do not generate replacement questions in this release. Exhaustion must identify unresolved concepts accurately.
- Read version-1 sessions without bulk migration. Treat unfinished area calibrations as surveys, preserving their pending question, counts, and budget; upgrade only when that checkpoint is next saved. Previously ended sessions remain ended.
- Preserve evidence IDs, records, concept scopes, projection rules, confidence thresholds, and teaching prerequisites. No evidence migration or automatic regrading.

The chosen limit is a configurable question budget. Elapsed-time enforcement remains outside v0.1.2.

## Acceptance criteria and validation

| Scenario | Required result |
| --- | --- |
| Weak connectivity; strong downstream knowledge | Survey continues through BFS, DFS, shortest paths, and remaining concepts. With fourteen turns or resumed blocks, independent unaided explanation/application pairs can establish downstream strengths while connectivity remains unresolved. |
| Forgotten terminology; retained application | Preserve the failed retrieval and successful application separately. Describe the distinction without claiming full active competence. |
| Default eight-turn survey | Without skips or bank exhaustion, sample all seven previously unassessed concepts before same-concept follow-ups. Report remaining capability uncertainty. |
| Budget below seven | Pause with explicit partial coverage; resume without restarting or losing progress. |
| Focused shortest-path readiness | Assess only terminology, connectivity, BFS, and shortest paths; permit a useful-boundary stop without surveying trees or DFS. |
| Prior evidence and corrections | Reuse direct assessments, honor corrections, and expose their references. Credentials, self-report, and downstream success never supply missing prerequisite credit. |
| Pause and interrupted saves | Preserve an unanswered prompt; recover an already saved answer once; consume a final-turn skip before pausing. |
| Exhausted prompts or all-correct answers | End with an accurate scope report, without fabricating questions, forcing failure, or implying area mastery. |
| Legacy state | Read old evidence and checkpoints; preserve ended sessions and evidence bytes; upgrade only a continued checkpoint. |
