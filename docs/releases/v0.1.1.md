## Discoveries incorporated into the guide

- Complete normalized background aliases are required for automatic mappings; arbitrary credentials are still saved without guessed concepts.
- The default diagnostic is capped at eight response turns. The internal Python budget parameter is not exposed by the CLI.
- Stopped diagnostics do not reopen; restarting retains performance evidence and assessed-question exclusions.
- Corrections change evaluations only, not recorded response text, assistance, question/rubric, or provenance.
- Inspection is read-only; `resume` can rebuild an existing plan, and explicit rebuild also writes learner metadata.
- Historical misconception entries can remain after improvement; the current estimate and its evidence must be inspected together.

These clarify existing behavior rather than change it. The original architecture, implementation milestones, and v0.1 validation records remain historical references.

## Bugs, inconsistencies, and limitations

No genuine implementation bug surfaced in the existing tests or the documented walkthrough; no runtime fix was needed or made. Discovery gaps in the previous documentation—terminal calibration stops, bounded question history, evaluation-only corrections, and resume/rebuild write effects—are now explicit.

While checking source, the guide was clarified to distinguish self-report-only skips (consumed per calibration run) from assessment question IDs (excluded across runs). This is existing behavior, not a new exclusion rule or a bug fix.

Interfaces worth considering separately later include clearer stop-versus-pause wording, bounded calibration/reassessment discoverability, handling response/assistance capture errors beyond evaluation corrections, and the distinction between read-only inspection and derived-plan rebuilding. Open-ended grading remains tutor judgment. The documentation does not provide new configuration, repair tools, backup, synchronization, or mastery controls.

The live walkthrough exercises declaration, calibration, skipping, stopping, and inspection. It does not repeat every v0.1 teaching/correction/resumption scenario. Those guide claims were checked against the unchanged implementation, existing 56-test suite, and historical v0.1 validation; no claim of exhaustive new live testing is made.
