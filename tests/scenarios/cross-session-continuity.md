# Scenario D: Fresh-Chat Continuity

This validates fresh Codex chats on the same checkout. A new Python process alone is insufficient. Synthetic testing uses one explicitly isolated state directory throughout; a personal learner uses Git-ignored `.learn/`.

1. Declare background, run a short adaptive calibration, and inspect its evidence-backed estimates.
2. Request BFS shortest paths. Demonstrate foundations, report rusty BFS, complete a concise refresher, and save unaided explanation plus fresh application.
3. End with the next target question unanswered and a saved teaching checkpoint. Inspect the evidence IDs, plan, and pending question.
4. Start a fresh Codex chat in this same repository. For synthetic validation, provide only the isolated state path and ask to continue, without supplying prior answers or the intended plan.
5. Confirm it reads the repository instructions, skill, and persisted state; skips demonstrated foundations; resumes the pending target; preserves uncertainty for untested concepts; and waits for a real response.
6. Answer, inspect the resulting record, and confirm both sessions contribute to the same learner model.

The fresh chat must not recreate onboarding or invent answers. Keep a review note linking the actual chat and recording its observed behavior. Cross-machine, clean-clone, backup, and synchronization checks are outside this MVP.
